# 决策模块使用说明

自然语言指令 → 任务序列 JSON。主入口：

```bash
python agent_demo_ui.py
```

先按第 1 节把软件装齐，再按第 2～4 节把智能体跑起来。以后展示只跑上面这一条。没连上 Dify 时见第 7 节。

---

## 1. 需要安装的软件

本模块不需要显卡。连智能体时依次装好 **Python、Docker Desktop、Git**，再执行 1.5 的 pip；浏览器用系统自带 Edge 即可。只跑本地规划（第 7 节）时 **只要 Python**。

### 1.1 Python 3.10 或更高

1. 打开 https://www.python.org/downloads/ ，下载 Windows 安装包。  
2. 安装时**务必勾选** `Add python.exe to PATH`。不要用微软商店里可能缺组件的精简版。  
3. 装完新开一个命令行窗口，输入：

```bat
python --version
```

应显示 `Python 3.10` 或以上。若提示不是内部命令，关掉窗口再开一次；仍不行就重装并勾选 PATH。

界面用的是 Python 自带的 tkinter，官网安装包一般已包含。

### 1.2 Docker Desktop（用来跑 Dify）

1. 打开 https://www.docker.com/products/docker-desktop/ ，下载 Windows 版。  
2. 安装后**重启电脑**（安装程序要求时一定要重启）。  
3. 再打开 Docker Desktop，等到右下角托盘图标变绿（Running）。第一次可能还要启用 WSL2，按它的提示完成即可。  
4. 新开命令行，输入：

```bat
docker --version
docker compose version
```

两条都能出版本号才算装好。图标还是灰色或红色时，不要点 `启动Dify环境.bat`。

### 1.3 Git（用来下载 Dify 源码）

1. 打开 https://git-scm.com/download/win ，下载并安装。  
2. 安装选项可一路默认。装完新开命令行，输入：

```bat
git --version
```

应显示 `git version ...`。

### 1.4 浏览器

Edge 或 Chrome 均可，用来打开 `http://localhost:8080` 配置 Dify。系统自带 Edge 即可，不必另装。

### 1.5 Python 依赖包

软件装好后，在本目录（`tiaozhanbei/decision`）执行：

```bash
pip install -r requirements.txt
```

会装这些包：

| 包 | 做什么 |
|----|--------|
| `requests` | 调用 Dify 智能体 API |
| `SpeechRecognition` | 把录音识别成文字 |
| `sounddevice` | 从麦克风录音 |
| `numpy`、`soundfile` | 处理音频数据 |
| `imageio-ffmpeg` | 把 m4a/mp3 转成能识别的格式 |

只打字、不录音也可以全装，体积不大。语音识别还需要能访问外网。

可选：界面右侧预览图需要 `pip install pillow`；不装也不影响下指令和出 JSON。

### 1.6 还要准备、但不是装软件

- **对话模型账号**：在 Dify 里配置 MiniMax（如 `minimax-m2.7`）或你已开通的模型，需要对应平台的 API Key。  
- **本模块的 Dify 应用 Key**：第 3 节在网页里创建，粘贴到 `agent_demo_ui.py` 开头的 `DIFY_API_KEY`。  
- **麦克风**（可选）：只有要点界面「开始录音」时才需要，在 Windows 设置里允许应用访问麦克风。  

Dify 本体不用单独安装程序，第 2 节的 bat 会用 Git 克隆、用 Docker 拉起。端口用 **8080**，不是 80804，不要用穿透地址。

## 2. 启动 Dify（偶尔做一次）

托盘里 Docker 图标变绿后，双击 `启动Dify环境.bat`。

它会检查 Docker / Git，把官方 Dify 克隆到用户目录，把网页端口改成 8080，再执行 `docker compose up -d`。第一次拉镜像比较慢。

也可以自己在终端做：

```bat
git clone --depth 1 https://github.com/langgenius/dify.git %USERPROFILE%\dify
cd /d %USERPROFILE%\dify\docker
copy .env.example .env
```

用记事本打开 `.env`，把 `EXPOSE_NGINX_PORT` 改成 `8080`，`EXPOSE_NGINX_SSL_PORT` 改成 `8443`，然后：

```bat
docker compose up -d
```

浏览器打开 `http://localhost:8080`。Dify 已经在跑就不要再点启动 bat。

---

## 3. 第一次在网页里配置

1. 注册管理员。
2. 点击“集成”，配置对话模型（如 MiniMax `minimax-m2.7`，或你已开通的模型）。
3.点击“工作室”-“创建” 导入 `workflows/workflow.yml`，点**发布**。
4. 创建 API Key（工作流页面：**发布** → **访问 API** → 创建密钥，复制 `app-` 开头那一串）。不要把 Key 发给无关的人。
5. **必须自己改** `agent_demo_ui.py` 文件开头的两行（大约第 38～40 行），界面以这里为准，不改就连不上你刚配的智能体：

```python
DIFY_API_URL = "http://localhost:8080/v1/workflows/run"
DIFY_API_KEY = "app-把你的密钥粘贴到这里"
```

- Dify 页面上的「Web 应用 URL」（`http://localhost/workflow/一串字母`）是给人在浏览器里打开的，**不要**贴进代码。容器内部是 80 端口，本机映射是 **8080**，所以 API 必须写成 `http://localhost:8080/v1/workflows/run`。  
- `DIFY_API_KEY` 换成你刚复制的 `app-...`。

改过 `workflow_code/` 之后，先执行 `python workflows/build_workflow.py`，再重新导入并发布，否则智能体还是旧规则。

## 4. 日常使用（展示走这里）

确认已改好 `agent_demo_ui.py` 里的 `DIFY_API_URL` 和 `DIFY_API_KEY` 后再运行：

```bash
python agent_demo_ui.py
```

在界面里输入指令、点快捷按钮，或开始/结束录音。连上后应看到 `source= dify_api:task_data`。

命令行测一条：

```bash
python agent/demo_voice_agent.py --cmd "拿取轴承-凸轮滚轮放到收纳盒" --sample 0001
```

默认写出 `../tasks/delivery_agent_auto.json`，可以交给仿真。

## 5. 可以说哪些指令

| 说法 | 行为 |
|------|------|
| `拿取轴承-凸轮滚轮放到收纳盒` | perceive → pick → move → place |
| `给我一个轴承-凸轮滚轮` | 只拿取 |
| `随便拿3个零件放到收纳盒` | 连续抓放 3 件，失败跳过继续 |
| `把轴承和螺丝放到收纳盒` | 多个具体零件按顺序抓放 |
| `把所有零件放进收纳盒` | 全部入盒（单臂） |
| `帮我把零件最多的区域装箱` | 最密区域装箱 |
| `帮我搬运一下料箱盒` | 未满先装，再搬运 |
| `帮我把所有零件装箱` | 多智能体装箱 + 搬运 |
| `把12个螺丝依次放到对应格子` | 按格子入格（视觉来自 `dataset_learn/0502`） |

动作含义：`perceive` 感知 · `pick` 拿取 · `adjust_pose` 调姿 · `move` 移动 · `place` 放置 · `transport` 搬运。指令里要有「放到 / 收纳盒 / 装箱」等，才会生成 move / place。

## 6. 生成的 JSON 给谁用

仿真读 `../tasks/delivery_agent_auto.json`，或本目录的 `delivery_for_simulation.json`。里面主要是：

- `sample_id`、`user_cmd`
- `task.object` / `task.coordinate` / `task.dest_coordinate`
- `task.tasks[]`：逐步 `action`

收纳盒坐标：`[0.30, -0.20, 0.0]`。

## 7. 没有连接智能体时

没有 Docker / Dify / 网络时，用 `offline/` 本地规划（规则与工作流相同）。

进入 `offline/` 双击 `一键生成任务JSON.bat`，或在本目录执行：

```bash
python offline/build_tasks_local.py
```

只需 Python，不必装上面的 pip 包、不必显卡。JSON 写在**本目录**（不是 `offline/` 里）：

- `delivery_for_simulation.json`：全量任务序列
- `delivery_scenario_35.json`：装箱 / 搬运 / 调姿等样例

抽查 `sample_id=0001` 的 `task.tasks`，应能看到 `perceive / pick / move / place`。

重建视觉输入：

```bash
python offline/extract_dataset.py
```

主界面连不上智能体时，也会自动走这套本地规划，不必先跑 bat。

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| `未知输出格式，可用字段：[]` | 工作流未发布，或 Key 不是当前应用 |
| 打不开 localhost:8080 | 等 Docker 变绿，再按第 2 节启动一次 |
| 语音识别失败 | 需要外网；或改用打字 / `--cmd` |
| 只生成 pick、没有 move | 指令加上「放到 / 收纳盒 / 装箱」 |
| `python` 不是内部命令 | 按第 1.1 节重装 Python，勾选 Add to PATH |
| Docker / Git 找不到 | 按第 1.2、1.3 节安装，装完**新开**命令行再试 |
